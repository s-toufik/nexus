# 2026-11-16 Homelab UI phone and desktop

## What we did
- Fixed the first message of a new conversation getting no answer: the page's route effect read store signals, so starting a conversation re-ran it and reopened an empty one. The effect now reads the store with `untracked()`, and `/assistant/new` is replaced by `/assistant/<id>` once the conversation exists.
- Phone: the tab bar and the More page are gone. A slim top bar (menu, the page's title, search or new conversation) and a menu that slides from the left, ChatGPT style: search, new conversation, recent conversations, then every page; the page stays visible on the right, tap or swipe left to go back. Pages scroll with the window, so iOS scrolling is native; the top bar and the composer are sticky. Compact spacing.
- Desktop: the sidebar folds to icons (button or `[`), the Assistant gets a details column on wide screens (assistant, stats, plan steps, last answer, Copy as text, Delete), `n` starts a new conversation.
- Conversations: delete one (bin, second click confirms) and Delete all; kept per account in the browser (`homelab-ui.agent.conversations.<username>`).
- Themes: eight now, generated by `scripts/themes.mjs` with a heading font each: Navy, Light, Contrast, Blossom and Lilac (Quicksand), Forest (Fraunces), Dragon Rider (Cinzel, after Fourth Wing), Wizarding (IM Fell English, after Harry Potter). Every text pair passes 4.5:1.
- People: the email is checked as you type; errors say what to do, a 404 means the gateway has no People API yet.
- README: rewritten sections for navigation, shortcuts, delete, where conversations are kept, the eight themes and the phone; 18 new screenshots including a themes collage and the phone menu.
- Checks: 162 tests, lint, typecheck, production build.

## What I learned
- An Angular `effect()` tracks every signal read inside it, including those read by methods it calls; wrap store calls that write state in `untracked()`.
- `ng serve` reloads code but not `angular.json`; new global styles (fonts) need a restart.
- Where conversations live: the browser keeps what you see; agent-runtime keeps its memory in MongoDB `agent_<agent>` (`checkpoints`, `checkpoint_writes`, TTL 7 days by `CONVERSATION_TTL`) and A2A tasks in PostgreSQL `agent_runtime.tasks_<agent>` (7 days, `A2A_TASK_TTL`). There is no delete endpoint on the server.
